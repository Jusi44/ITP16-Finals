# Phase 0 — Bootstrap Plan

Status: approved with changes; ready to implement.
Package versions verified against the npm registry with `npm view <pkg> version` and peer-range checks on 2026-10-20.

## Goal

Create a buildable four-workspace monorepo (`/web`, `/api`, `/db`, `/infra`) with shared TypeScript, ESLint/Prettier, local PostgreSQL 16 (`citext` only), `.env.example`, `.gitignore`, Docker Compose, and a README. No product behavior beyond a stub `/api/health` and a placeholder web shell.

## Understanding

1. SmartCanteen is a canteen POS + inventory app with `ADMIN` and `STAFF` roles, signing in by username/password.
2. Five main screens: Dashboard, Inventory, Orders (POS), Analytics/Reports, Personnel; plus Login and the Stock History/Audit Trail sub-page.
3. `Personnel` is ADMIN-only; Audit Trail is opened from Reports and has a back button.
4. Four entities: `User`, `FoodItem`, `Sale`, `StockRecord`.
5. Everyone sees Dashboard, Inventory, Orders, Reports; only ADMIN manages users.
6. A sale validates quantity 1..stock, reads price from the DB, inserts a Sale + `SALE` StockRecord, and decrements stock in one transaction.
7. Insufficient stock returns `409 INSUFFICIENT_STOCK`.
8. Restock increments stock and writes a `RESTOCK` record atomically.
9. Low stock is `current_stock <= min_threshold`; out of stock is `0`; colour/progress-bar rules are prescribed.
10. Dashboard: menu/low-stock cards, 7-day revenue bars with top product per day, attention list, top 3 sellers.
11. Orders: item selection, quantity stepper, `COMPLETE PAYMENT • ₱total`, 1.5s `SUCCESS` overlay.
12. Reports: Today/7 Days/All Time, net revenue, transaction count, newest-first list, share/CSV (CSV in Phase 4).
13. Audit Trail: item snapshot, "Added to stock by"/"Sold by", `+N`/`-N` badges, newest-first.
14. Money is `numeric(12,2)`/₱, timestamps are `timestamptz` UTC, day bucketing uses `APP_TIMEZONE` (Asia/Manila).
15. Auth is server-side with DB sessions, argon2id, httpOnly cookie; role checks and validation are enforced server-side; SSE is Phase 4.

## Key Decisions and Rejected Alternatives

1. **npm workspaces, no Turborepo/Nx** — the repo is small and npm is sufficient.
2. **Package names `@smartcanteen/*`; folder names unchanged** — AGENTS commands like `-w api` still work by path.
3. **`/db` owns Drizzle schema, migrations, seeds; API delegates `db:*` scripts** — keeps `/db` meaningful and preserves AGENTS commands.
4. **React 18.3.1** — AGENTS pins React 18; React 19.3.1 was rejected despite being current.
5. **TypeScript 6.0.3** — newest major supported by typescript-eslint 8.72 (`<6.1.0`). TypeScript 7.0.2 (the native port) was rejected because the lint toolchain does not support it yet.
6. **Vite 8.3.4 + @vitejs/plugin-react 6.1.2** — newest stable pair; plugin 6 requires Vite 8. Node 24 satisfies both engines. The earlier Vite 7 rejection was solely the Node 20 constraint, which no longer applies.
7. **Vitest 5.0.5** — newest stable; requires Node `^22.12 || ^24` and supports Vite 8. The earlier Vitest 3 rejection was solely the Node 20 constraint.
8. **ESLint 10.13.0 + @eslint/js 10.0.1** — typescript-eslint 8.72 and both React plugins declare ESLint 10 support.
9. **Tailwind 4.3.3 + @tailwindcss/vite 4.3.3** — newest stable; CSS-first config removes PostCSS/autoprefixer from the setup. Tailwind 3.4.19 was rejected as older than necessary.
10. **Zod 4.6.7** — current major; validation uses explicit `safeParse`, not a Fastify type provider.
11. **`@node-rs/argon2` 2.2.2** — prebuilt binaries, no Windows build toolchain; satisfies the argon2id requirement.
12. **DB-backed sessions** — random opaque token in an httpOnly cookie; only its SHA-256 hash is stored in `sessions`; 8-hour expiry; deleting a user cascades and logout deletes the row, so access is cut immediately. JWT was rejected for that reason.
13. **Auth hardening** — SameSite=Lax, Origin check on mutations, JSON content-type required; `Secure` mandatory in production with startup failure otherwise; `__Host-` cookie prefix in production.
14. **Postgres `16-alpine` + citext init SQL** — `gen_random_uuid()` is native, so `pgcrypto` is not installed. Phase 1 migration 0000 will create `citext` for RDS as well.
15. **Health path `/api/health`** — matches CloudFront/ALB `/api/*` routing.
16. **Infra skeleton only** — no CDK dependencies until Phase 6.
17. **Trust proxy** — `TRUST_PROXY` is configurable (false by default; set to the ALB/CloudFront hop count in production) rather than blindly trusting every proxy.
18. **Login enumeration protection** — unknown usernames still run a dummy password hash and return the same error.
19. **Role policy** — STAFF keeps full parity (everything except Personnel); all rules will live in `api/src/auth/permissions.ts` in Phase 2.
20. **Edit stock has no audit record** — Android parity for now; noted as a product decision that may change later.
21. **Test DB** — Phase 2 uses a separate `smartcanteen_test` database and truncates between tests; the runner refuses any database whose name does not end in `_test`.

## Risks

- Docker is not installed on this machine; all Docker-dependent checks will be marked NOT VERIFIED until the user installs Docker Desktop.
- The host Postgres port may conflict with a local installation; `POSTGRES_PORT` makes it configurable.
- Alpine images could lack `citext`; if init fails, switch to the Debian `postgres:16` image.
- Cookie `Secure` is environment-gated; production startup must fail without it.
- No pagination yet; transaction and audit lists grow unbounded until Phase 2.
- SSE through CloudFront/ALB may be buffered or timed out; 5s polling is the fallback (Phase 4).
- Money precision must use decimal strings/integer minor units; no JS floats.
- Concurrent sales depend on a conditional `UPDATE ... WHERE current_stock >= qty` in a transaction and need the Phase 2 race test.
- No self-service password reset; rotation depends on the Phase 2 ops script.
- `npm install` with AWS CDK deferred keeps this phase light; Phase 6 will add those dependencies.
